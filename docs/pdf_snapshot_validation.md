# PDF: проверка неизменности и полноты отчёта

Исправление подготовлено на базе `707e88f`. Схема БД остаётся `20261030_25`.
Backend runtime, расчёты и миграции не изменены.

## Подтверждённые дефекты

1. `assertSameSnapshot()` сравнивал `JSON.stringify` вместо значений JSON.
   Эквивалентные объекты с различным порядком ключей, включая вложенные объекты,
   считались изменившимися. Регрессионный тест падает на исходной версии и проходит
   на исправленной. Никакие числовые допуски, приведение типов или игнорирование
   полей для обхода проверки не добавлены. Порядок элементов массивов значим.
2. `assertVisibleRows()` использовал `Map<key,row>`. В `product_reports._products`
   SQL группирует по артикулу, коду и названию, а `product_key()` отдаёт приоритет
   коду. Различные корректные строки могут иметь одинаковый ключ. Map оставлял
   только последнюю, поэтому сравнение полного ответа с исходными строками могло
   ошибочно завершиться отказом. Теперь сравниваются все вхождения ключа, с учётом
   количества и всех полей. Потеря, изменение или нехватка повторяющейся строки
   блокируют экспорт. Сам порядок печати определяется полным ответом и таблицей.

Это воспроизводимые причины ложного отказа в коде. Ответы конкретного проблемного
production-запроса не получены; нельзя утверждать, какой из дефектов сработал там.
При продолжающейся ошибке полезен новый безопасный код проверки, без выгрузки
клиентских данных или отчёта в console.

## Защита и диагностика

- `data_changed`: отличаются данные/итоги/число строк/периоды.
- `parameters_changed`: параметры изменились во время подготовки/захвата PDF.
- `incomplete_rows`: full-ответ не соответствует total или потерял исходные строки.
- `invalid_row_identity`: невозможно идентифицировать строки.
- Дополнительно выводится безопасное имя проверки: snapshot/row_count/row_identity/row_presence/row_content. Значения полей не выводятся.
- Другие ошибки помечаются как ошибка подготовки PDF; числовые значения и данные
  клиентов не добавляются в диагностический код или console.

Параметры повторно проверяются после prepare и перед отправкой HTML. Inert,
защита от повторного нажатия, abort/timeout и восстановление интерактивности
сохраняются. Добавлены проверки totals и стабильных заголовков full-ответов;
в детализации продаж по товарам теперь сравниваются также исходные строки.
В детализациях продаж товаров/категорий/магазинов добавлены доступные кнопки PDF:
основную кнопку страницы перекрывает открытое окно.

## Проверки

- Frontend: 130 тестов, 14 файлов; сборка `tsc -b && vite build`.
- Backend PDF и full datasets: 14 тестов, включая opt-in реальный Chromium.
- Настоящий браузер: все восемь страниц, синтетические API-ответы, фактический
  ASGI PDF handler и Chromium; извлечение текста `pdftotext`, проверка A4/pages.
  Полные ответы возвращаются с рекурсивно переставленными ключами объектов.
- Проверены все500клиентов RFM,550товаров в обоих товарных отчётах,500кандидатов.
  В открытых детализациях товаров/категорий/магазинов первоначально50из120продаж;
  в PDF проверяется наличие последней `PDFSALE-119`.
- Проверены реальные изменения числа/типа/ID/поля, отсутствие строк, повторения
  ключей, смена фильтров во время prepare, ручной повтор и восстановление UI.

## Ограничения и установка

Экспорт не создаёт серверный version token для всей БД. Сравнение защищает
загруженные строки и итоги, но не является транзакционной заморозкой нескольких
HTTP-запросов. Изменение ещё не показанных строк с одновременно неизменными
итогами нельзя доказать по первоначально усечённому ответу. Это ограничение
прежнего контракта; проверки не ослаблены. Для строгого snapshot всех данных при
конкурирующих импортах нужна отдельная серверная версия/единый snapshot API.

Production не проверялся и не изменялся. Проверки не доказывают вместимость любого
production PDF при1.9ГиБRAM. Существующие лимиты, очередь и guards backend оставлены.
Сборка даёт предупреждение Vite о размере chunk; код не ограничивает строки ради
уменьшения PDF.

После review/merge нужен новый **frontend image**, собранный вне VPS из утверждённого
коммита. Обновить frontend готовым образом по существующей безопасной процедуре,
не выполнять сборку на VPS. Backend уже707e88f с Playwright/Chromium совместим;
backend image ради этого исправления пересобирать не требуется. Миграций нет.
После установки проверить PDF обычного отчёта и открытой детализации вручную.
