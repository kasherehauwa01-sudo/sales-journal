# Страница импорта: интерфейс по задачам

Ветка основана на PR177 (`c2eabb6`): изменения только frontend, без изменений
backend, API, моделей, миграций, updater и production-конфигурации.

## Что изменилось

- Три самостоятельных раздела: **Контроль полноты**, **Загрузка файлов**,
  **Журнал загрузок**. Состояние фильтров, выбранных файлов и несохранённых настроек
  сохраняется при переключении внутри страницы.
- В контроле — навигация по существующим подразделениям, пропускам, исторической
  сверке, уведомлениям и настройкам. Чёткие счётчики, статус/дата и отдельный блок
  проверки периода. Ручное подтверждение дня находится в раскрывающемся блоке.
- Историческая сверка показывает прогресс по реальным счётчикам backend. Область
  сверки и фильтр сохранённых результатов визуально разделены. Кнопки паузы и
  продолжения показываются только в подходящем состоянии. Исправление шаблонов
  находится в отдельном раскрывающемся блоке; прежние подтверждения сохранены.
- Работает фактическое перетаскивание файлов. Выбранные файлы можно добавлять и
  убирать до отправки, список можно очистить. Неподдерживаемые расширения явно
  отклоняются интерфейсом; backend остаётся обязательной границей валидации.
  Дедупликация/переимпорт остаются прежней серверной логикой, клиент их не подменяет.
- Один явный запуск импорта, синхронная защита от двойного клика, блокировка
  редактирования списка при отправке. Успешный ответ называется «переданы на
  обработку», а не «продажи импортированы»: результаты нужно проверить в журнале.
- В журнале — поиск по имени, фильтр статуса и понятные состояния загрузки,
  недоступности, пустого списка и отсутствия совпадений. API возвращает последние
  **200** записей; фильтры работают только по ним и не выдают их за всю историю.
- Журнал обновляется каждые5 секунд при просмотре или наличии известных queued/
  processing импортов. GET не перекрываются. Ошибка чтения журнала не подменяет
  его пустым списком и не стирает ошибку отправки файла.
- Окно ошибок использует native dialog: Escape, фон, возврат фокуса. Отображение
  ошибок строк/лога сохранено. Формы адаптивны, широкие таблицы прокручиваются
  внутри своей области, а не растягивают всю мобильную страницу.

Все существующие административные подтверждения, срок00:20 МСК, права доступа и
payload контрольных API сохранены. Открытие страницы, выбор файлов и переключение
разделов не запускают импорт, историческую сверку, исправление правил или письма.

## Проверки

- `npm test`: **167 passed**,18 файлов, в том числе8 новых сценариев ImportsPage.
- `npm run build`: TypeScript/Vite PASS; прежнее предупреждение о JS chunk>500КБ.
- Локальный Chromium с полностью подставными API: desktop1440px/mobile390px,
  навигация, явная отправка одного synthetic файла, журнал/фильтры, native dialog
  Escape/focus return, read-only preview, отсутствие body overflow/JS errors.
- Сохранены проверки исторической сверки start/pause/resume; раскрытие редкого
  действия в тесте теперь соответствует реальному действию пользователя.
- Backend-тесты/миграции не запускались: серверный код не изменён.

Воспроизведение без production:

```bash
cd frontend
npm test
npm run build
npm run dev -- --host 127.0.0.1 --port 18528
# В другом терминале, из корня repo с установленным Playwright/Chromium:
python frontend/tests/browser/import-workspace-smoke.py
```

Browser smoke принимает только localhost/127.0.0.1, перехватывает все API и
блокирует внешние запросы, включая Google Fonts (используется системный fallback).
Файл отправляется только в подставной route, сервер импорта не запускается.
Скриншоты — синтетические, не production-данные.

## Внедрение

Для этого PR достаточно нового готового **frontend**-образа. Backend PR177 со
схемой27 должен быть установлен отдельно по утверждённому плану до использования
исторической сверки. Новых миграций этот UI PR не требует. Сборка вне FirstVDS,
проверка и обновление frontend штатным подготовленным updater; автоматический
деплой/merge не выполнялись. Для отката интерфейса достаточно прежнего frontend
image, без отката backend или PostgreSQL.
