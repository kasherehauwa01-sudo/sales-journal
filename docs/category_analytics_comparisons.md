# Сравнения и продажи товаров в аналитике категорий

На странице нет периода «Сегодня»: сегодняшние данные штатно исключаются
из текущей недели/месяца. KPI одновременно показывают сравнения с аналогичными
датами прошлого года и предыдущим периодом. Для текущей недели берутся те же
дни прошлой недели, для текущего месяца — такие же дни прошлого месяца с
ограничением последним днём короткого месяца. Для полного прошлого месяца
берётся полный предшествующий календарный месяц. Произвольный диапазон
сравнивается с непосредственно предшествующим диапазоном той же длины.
29 февраля прошлого года заменяется на 28 февраля, если год невисокосный.

Рост и падение имеют независимые переключатели «Предыдущий год» и
«Предыдущий период». Переключение использует результаты уже сформированного
отчёта без сетевых запросов; открытие категории из этих блоков использует
выбранный режим сравнения. Диаграмма выручки имеет отдельный переключатель сравнения: оба набора
категорий загружены заранее, ТОП-10/20/Все применяются к выбранному набору.
Над диаграммой показаны фактические даты сравнения. Основная таблица
остаётся сравнением с предыдущим периодом. Порядок легенды: сравниваемый год/период, текущий; значения и цвета
рядов не перепутаны. Excel сохраняет существующее сравнение с предыдущим
периодом, используя исправленные календарные границы.

Один отчёт читает три периода последовательно, с общей картой CatalogVR;
продукты, которые есть только в прошлом году, также включаются в карту.
Это дополнительные агрегирующие SQL относительно двух периодов, без второго
параллельного построения отчёта. Нагрузка на production не измерялась.
Существующая кнопка явного формирования и запрет параллельных действий сохранены.

Строки товаров в детализации доступны мышью и клавишами Enter/пробел.
Продажи запрашиваются по 50 документов (не более 100 на API-страницу), с
периодом, магазином, менеджером и видом покупателя последнего сформированного
отчёта. Код имеет приоритет над артикулом, название используется только для
товаров без обоих идентификаторов. EXISTS исключает повторение документов
с несколькими строками одного товара. Для этого перехода CatalogVR не нужен.
Показывается текущий период: для товара, продававшегося только в сравнительном
периоде, список будет пустым. Сумма, базовая сумма и скидка относятся ко всему
документу. Дальнейший переход открывает существующую карточку продажи.

Добавлены проверки календарных границ/високосного года, общей карты трёх
периодов, раздельных сумм сравнения, SQL-фильтров и отсутствия дублей документов,
пустых страниц, локальных переключателей и пути товар→продажи→карточка.
Production, миграции и конфигурация не затрагивались.
