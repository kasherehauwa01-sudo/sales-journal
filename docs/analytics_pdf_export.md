# PDF аналитических отчётов

Реализация в ветке `feat/full-analytics-pdf-export`, база PR — `a56c677` (main).
Исправление больших SQL-выборок и dashboard-sales (PR #166) уже входит в main.
При актуализации сохранены маршруты CHURN_RISK и настройки прав Docker из main.
Никакой публикации, миграций, изменения production или автоматизации не выполнено.

## Архитектура

Общий `PdfExportButton` фиксирует параметры сформированного отчёта, блокирует
редактирование страницы через `inert` и не допускает повторного нажатия. Если
фильтры изменены после формирования, сначала требуется сформировать отчёт снова.
Верхняя панель каждого из восьми отчётов содержит кнопку «Скачать PDF»; в открытой
детализации товарной аналитики кнопка также доступна внутри карточки.

Страницы с ограниченными таблицами по нажатию PDF запрашивают `full=true` у
существующего обработчика. Используются те же datasets, фильтры, классификация,
сортировки и формулы; флаг снимает только ограничение выдачи/пагинацию. Обычные
запросы без флага сохраняют прежний объём. Параметры для PDF берутся из snapshot,
а не из черновика фильтров. Видимые строки и KPI сверяются с полным ответом;
при изменении данных предлагается заново сформировать отчёт. Проверяется равенство
числа строк и `total`; устаревший backend, игнорирующий full, не выдаётся за полный.
Для сезонности проверяются metadata, видимые строки и отсутствие next_cursor;
full игнорирует навигационные курсоры, сохраняя поисковые/датовые/магазинные фильтры.
Открытые пагинированные детализации продаж товаров/категорий/магазинов также
получают полный набор. После экспорта исходные данные страницы восстанавливаются.

Это не новый долговременный snapshot БД. Между отдельными HTTP-запросами возможны
изменения источников. Проверка KPI и видимых строк выявляет расхождения, но не
является доказательством общей транзакции PostgreSQL между всеми запросами.
Графики/карточки уже сформированной страницы сохраняются; для «Продаж по товарам»
расширение таблицы не меняет существующий top-график. Если нужна строгая единая
историческая ревизия всех источников при конкурентном импорте, потребуется отдельный
серверный versioned snapshot; в этой задаче он не вводился.

Далее общий capture сохраняет DOM, вычисленные цвета/типографику/оформление,
векторные SVG Recharts и Canvas как PNG; ожидает fonts.ready, изображения и layout.
Анимации графиков этих страниц отключены. Интерфейс управления заменяется
метаданными snapshot; информационные карточки, таблицы, выводы и рекомендации
сохраняются. Разворачиваются информационные details. Токены/служебные data-атрибуты
не переносятся. Стили скролла снимаются. Широкие таблицы разбиваются на блоки до
девяти колонок с повторением колонок имени/идентификатора: все строки и столбцы
сохраняются, таблицы не превращаются в нечитаемую единственную картинку.

`POST /api/reports/pdf` принимает только снимок HTML, известный тип отчёта, период
и безопасное имя файла; URL для загрузки не принимает, к БД/ClientsVR/Calltrack не
обращается. HTML проходит allowlist-санацию. Chromium запускается с новым пустым
контекстом без cookies, с выключенными JavaScript/service workers, offline и
запретом всех сетевых запросов. CSP разрешает только встроенные стили и data-image.
Изображения file/http и CSS внешних ресурсов удаляются; executable/embedded HTML
не допускается. Заголовки/период экранируются. PDF возвращается непосредственно
приватным ответом `no-store`, без публичных файлов или ссылки хранения.

Печать: A4 landscape, цветной фон, встроенная поддержка кириллицы DejaVu Sans,
колонтитулы с названием/периодом и нумерацией, повторение thead, запрет разрыва
SVG-графиков и KPI. Таблицы печатаются шрифтом 11 CSS px (8.25 pt).

## Ресурсы и ошибки

Генерация и полная загрузка сериализуются с существующими тяжёлыми отчётами
через общий межпроцессный механизм. Browser создаётся только по запросу и
закрывается в finally. PDF держится в памяти; временных публичных PDF нет.
Ожидание слота ограничено существующей политикой, renderer — 90 сек, клиент —
120 сек на загрузку полного набора и печать. Изменение общей политики очереди не
потребовалось. При нехватке RAM (доступно менее 512 МиБ) печать отклоняется 503.
Это проверка headroom, не жёсткая cgroup-квота Chromium и не гарантия общего RAM.

Нет лимита количества строк с молчаливым усечением. Есть защитный предел тела
HTML-запроса 32 МиБ и временные/ресурсные пределы: превышение возвращает ошибку,
а не сокращённый PDF. Очень большие отчёты всё ещё требуют значительной памяти
браузера пользователя и VPS. На текущем малом VPS сначала нужен контролируемый
замер; увеличение памяти PostgreSQL для этого функционала не требуется.

Внешнее изображение, запрещающее чтение Canvas через CORS, приводит к понятной
ошибке; оно не пропускается молча. Для таких изображений требуется корректный
same-origin/CORS-контракт источника. Широкие таблицы с объединёнными ячейками
сейчас отклоняются, если их нельзя безопасно разбить; обычные таблицы восьми
отчётов проверены. PDF адаптирует экранную компоновку: фон/цвета/данные сохраняются,
но это не обещание побитового/pixel-perfect совпадения браузеров и всех шрифтов.

## Локальный повтор проверок

```sh
# В backend-окружении после обычной установки requirements-test.txt:
RUN_PDF_BROWSER_TESTS=1 PYTHONPATH=backend pytest -q \
  backend/tests/test_report_pdf.py backend/tests/test_pdf_full_datasets.py
npm --prefix frontend test
npm --prefix frontend run build
```

Для реального браузерного smoke test нужны локальный Chromium и утилиты Poppler
(`pdfinfo`, `pdftotext`, `pdftoppm`); они нужны для проверки, не для backend runtime.
Запустить локальный Vite (не production):

```sh
npm --prefix frontend run dev -- --host 127.0.0.1 --port 5174
# Во втором терминале, из корня проекта:
PYTHONPATH=backend python backend/scripts/verify_report_pdfs.py \
  --base-url http://127.0.0.1:5174/vr/sales \
  --output /tmp/analytics-pdf-test
```

Скрипт принимает только localhost/127.0.0.1, все API подменяет синтетическими
фикстурами, кроме печати через отдельное ASGI-приложение без production lifespan.
В production запускать этот test harness не нужно.

## Зависимости и установка после согласования

Добавлена Python-зависимость `playwright==1.64.0` — именно с ней выполнены проверки.
Backend Dockerfile устанавливает distro Chromium и `fonts-dejavu-core`. Используется
`/usr/bin/chromium`; загрузка дополнительного Playwright browser bundle не нужна.
`REPORT_PDF_CHROMIUM` при нестандартной локальной установке задаёт путь к executable,
а не бизнес-флаг. Конфигурация production/feature flags не изменена.

Нужны новый backend-образ (одного restart старого образа недостаточно) и новая
frontend-сборка одной версии. Сборку выполнять в существующем проверенном build
pipeline, сохраняя реальные V3 build context, tag/digest, volumes, сети, ключи и
startup-проверки. Нельзя заменять действующий V3-образ случайным старым Compose tag.
Миграций, изменений моделей/БД, Calltrack, worker-флагов и задач нет. Контейнер
PostgreSQL пересоздавать не требуется.

До разрешённого обновления:

1. Проверить фактические SHA/diff production и совместимость базы кода; не
   перезаписывать серверные изменения. Сделать обычный согласованный backup кода/
   образов, сохранить предыдущие image digest и frontend asset.
2. Убедиться, что маршрут `/vr/sales/api/reports/pdf` попадает под тот же защищённый
   ingress. Проверить отсутствие открытого backend-порта в обход него. Не
   добавлять исключений авторизации или новых публичных URL для PDF.
3. Проверить наличие Chromium и DejaVu в новом образе; в isolated staging сделать
   PDF smoke test. Проверить достаточно RAM и timeout/proxy body limits. Для этой
   задачи production и Docker не запускались.
4. По отдельному разрешению обновить frontend/backend одной версией. Использовать
   существующую процедуру V3 и startup без произвольного запуска Alembic.
5. Проверить health/обычные отчёты/Excel и PDF каждого отчёта. Сверить показатели,
   последние строки, колонки, фильтры, графики, имя и период; проверить ошибку
   неавторизованного доступа и один контролируемый большой отчёт с мониторингом RAM.
6. При сбое вернуть предыдущую пару backend image + frontend asset существующим
   способом, сохранив конфигурации и volumes. Откат БД не нужен, схемы не менялись.
   Не активировать CHURN_RISK/SHADOW worker или задания в рамках этого обновления.
