# Динамика продаж: сравнение и клиенты

«Прошлый год» сравнивает аналогичные даты прошлого года (29 февраля безопасно заменяется 28-м). «Предыдущий период»: полный месяц с полным предыдущим месяцем, неполный текущий месяц с теми же днями предыдущего месяца, неделю/её загруженную часть с теми же днями предыдущей недели. Произвольный полный календарный месяц также сравнивается с предыдущим календарным месяцем; иной произвольный диапазон — с непосредственно предыдущим диапазоном той же длины. Текущий день по-прежнему исключается существующим effective_period.

Фильтр «Клиент» — выпадающий список с чекбоксами и поиском внутри. Список загружается только при открытии из /reports/sales-dynamics/client-directory, а не из ограниченного первыми 1000 /filters. Поиск выполняется по всем именам журнала в PostgreSQL; выдача по 100 имён, дальнейшие страницы кнопкой «Показать ещё». Курсор по нормализованному имени исключает дубли регистра/пробелов и не требует полного COUNT. % и _ в поиске — буквальные символы. Выбор сохраняется при поиске/дозагрузке. Запросы отменяются при закрытии/смене поиска, устаревшие ответы не используются. Никаких запросов Clients VR за справочником. Запрос может сканировать источник продаж; production нагрузка не измерена, индексы и конфигурация не менялись. Пустой выбор — все разрешённые клиенты. Выбранные имена передаются повторяющимся GET clients; backend пересекает их с фильтрами менеджера/типа покупателя и одинаково применяет к обоим периодам, KPI и графику. Нормализация регистра/крайних пробелов сохранена. Старый одиночный параметр client поддерживается. Изменение выбора не запускает отчёт: требуется существующая кнопка формирования.

Логика периода изменена только в sales_dynamics_report, не в других отчётах. Миграций/новых таблиц/таймаутов/параллелизма/TTL изменений нет. Production API/БД не использовались, деплой не выполнялся.
